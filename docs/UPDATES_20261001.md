# Standalone Update: 2026-10-01

## Included

- S1, S2 and S3 GUIs retain their existing launchers and controller choices.
- S3 adds a DES-only physical-timing workflow, finite loading resources,
  causal heralding, endpoint delivery, exact Bell-vector conditional states,

- The native scheduler rejects negative delays and scheduling into the past.
- A safe export tool preserves the standalone framework and repository history.

## Interpretation

The historical S3 batch model can be limited by per-cycle processing caps.
Its flat rate and similar long-T2 curves should not be used as a universal
comparison against S1. The physical-timing workflow exposes service and
loading resources and distinguishes delivered counts from a fidelity-qualified
service. Results depend on memory policy, loading opportunities, optical
assumptions, finite capacity and the selected qualification threshold.

The included Windhof-Kirchberg pass is a simulated replay fixture, not a
measured satellite campaign. Geometry, channel traces and model settings are
retained to reproduce the study; changing them defines a different scenario.

QUASAR detector presets and compensation options support sensitivity analysis.
They do not establish calibrated mission fidelity. Source statistics,
calibration, receiver noise and residual compensation errors remain important
assumptions to validate against mission or laboratory data.

## Distribution

This export contains executable models, GUIs, regression tests, static assets
and the compact S3 replay inputs. It excludes environments, generated study
outputs, the original Excel workbook and manuscript PDFs. Existing data
licensing notices are retained with their assets.

## Verification

The exported tree was tested with Python 3.9 in the existing local research
environment. Framework, S3 timing/GUI, QUASAR and analytical link-budget tests
were run. The optional private-workbook comparison was skipped. All five GUIs
loaded through Streamlit's application test harness. S1, S2 and S3 DES smoke
runs produced plots, a short S3 physical-timing study produced a report, and a
Ground DES + SDN Ryu smoke run completed using the separate legacy Ryu
environment. All exported Python modules compiled successfully.

This is software verification, not mission-model validation. A fresh online
dependency installation and full Ryu runs for S1 and S2 were not repeated for
this export.
